# Calculator

A four-function keypad calculator with keyboard input. Rust owns an opaque
`Calculator`; frontends send typed `Key` values and read its display string.
Keys pass as scalar enum tags; calculator state stays in Wasm.

Operations execute left to right, repeated equals repeats the last operation,
and percent divides the current entry by 100. Results use 12 significant digits;
this is a floating-point desk calculator, not a financial decimal calculator.
Clear or a new number recovers from division-by-zero or overflow.
The page disposes its Rust state on exit, retaining it for back/forward caching.

The minimal stateless formula example is now [`../hello-world`](../hello-world/README.md).

## Setup

This directory is an independent Rust/OCaml project. Its Cargo workspace,
Dune workspace, npm dependencies and build outputs are local to this directory.
The Rust dependencies point at the SDK crates in this checkout for development.

Install Rust with the `wasm32-unknown-unknown` target, Node.js and Dune 3.24.2.
Dune uses this project's checked-in dependency lock.

```sh
make -C ../.. install        # Install ocamljs_pack once
make deps                    # npm ci for this project
make build
```

`make build` writes Rust artifacts to `rust/target/`, OCaml artifacts to
`_build/`, bindings to `generated/`, and site assets to `dist/melange/` where applicable.
It does not build other projects or run tests.

## Build commands

Run in this directory, with the Rust/OCaml toolchains and this project's npm dependencies installed:

```sh
make wasm                    # Rust library to WebAssembly
make bindings                # OCaml bindings and JavaScript bridge
make frontend                # OCaml to JavaScript
make bundle                  # Browser JavaScript bundle
make assets                  # HTML, CSS, Wasm and runtime in dist/melange
make build                   # Complete chain; no test compilation/execution
make serve                   # Build and serve at http://localhost:8000
make clean
```

Each step builds its prerequisites. `tests/ocaml/Test.ml` belongs to explicit validation,
not the normal frontend build. Rust commands run inside `rust/`; `ocamljs_pack`
is the installed binding generator.

Application entry points live in `src/ocaml/Main.ml` (Melange),
`src/js_of_ocaml/Main.ml` and `src/rescript/Main.res`. The js_of_ocaml frontend
uses shipped `Dom_html`, `Dom` and native promises directly, without a browser/UI/async
compatibility layer. Melange and ReScript retain their own browser declarations
and UI helpers. All entry points initialize Rust through `Bindings.Wasm.load`.
HTML and CSS live in `web/`; browser JavaScript is generated by the compilers
and bundler. Normal builds perform no frontend syntax conversion or test execution.

Run `make matrix` at the SDK root for all three compiler variants, or
`make prepare` and `make test` for bounded validation. Matrix sites are in
`dist/<backend>`; `make serve PORT=8001` selects another port for the normal site.

The normal Rust library contains only the calculator state machine. Additional
binding-conformance cases live in `tests/rust/conformance.rs`, enabled by the
`conformance` feature during the explicit compiler matrix validation.
