# Borrowed result encoding

Borrowed encoding publishes the existing typed binary ABI while reading large Rust
records and collections by reference. The caller receives the ordinary owned OCaml
record, variant, list and `result` types. Rust references never cross the ABI.

## Opt in to structural borrowing

Add `borrow` to a structural type's binding attribute:

```rust
#[ocamljs_bindgen::ocamljs_bindgen(borrow)]
pub struct Row {
    pub name: String,
    pub values: Vec<u32>,
}
```

This generates `EncodeRef` alongside the usual owning codecs. Every nested
structural field must support `EncodeRef`; opt in to those records and enums too.
The runtime supports borrowed primitives, strings, options, results, arrays,
slices, vectors, tuples, maps and shared `Rc`/`Arc` pointees. `Arc<T>` keeps the
same wire and OCaml representation as `T`.

Borrowing is explicit. Existing owning records can still contain opaque handles
and host references. Those values cannot opt in to borrowed structural encoding.
Callbacks keep their existing exported-argument acquisition path; opaque Rust
objects may retain them internally. An owning field in a projection can still
transfer its own resources through the ordinary owning codec.

## Project from the owned declaration

`#[derive(ocamljs_bindgen::EncodeProjection)]` generates
`NameProjection<P0, P1, ...>` from a concrete record or enum named `Name`. Each
field gets a projection parameter constrained by `EncodeAs<OwnedFieldType>`.
Record field order and enum tags come from the owned declaration, so a separate
handwritten wire layout is unnecessary.

Use an owned field directly, borrow an `EncodeRef` field, or use another typed
projection. `SequenceProjection(iterator)` encodes an exact-size iterator as a
`Vec<T>`. Its items must encode as `T`; for example, an iterator of `&Row` can
encode `Vec<Row>` without constructing a temporary vector of rows or references.

## Return a complete encoded result

This example uses the actual projection names generated by the derive:

```rust
use ocamljs_bindgen::{
    ocamljs_bindgen, EncodeProjection, Encoded, ResultProjection,
    SequenceProjection,
};

#[ocamljs_bindgen(borrow)]
pub struct Row {
    pub name: String,
    pub values: Vec<u32>,
}

#[ocamljs_bindgen]
#[derive(EncodeProjection)]
pub enum Rows {
    Keep,
    Replace { rows: Vec<Row> },
}

#[ocamljs_bindgen]
#[derive(EncodeProjection)]
pub struct Update {
    pub revision: u32,
    pub rows: Rows,
}

#[ocamljs_bindgen]
pub enum Error {
    Missing,
}

#[ocamljs_bindgen(opaque)]
pub struct Store {
    revision: u32,
    rows: Vec<Row>,
}

#[ocamljs_bindgen]
impl Store {
    pub fn publish_rows(&self) -> Encoded<Result<Update, Error>> {
        let projection = UpdateProjection {
            revision: self.revision,
            rows: RowsProjection::Replace {
                rows: SequenceProjection(self.rows.iter()),
            },
        };
        Encoded::new(ResultProjection(Ok::<_, Error>(projection)))
    }
}
```

`ResultProjection` retains the normal `Ok`/`Err` envelope while projecting the
successful value. The generated `Store.publish_rows` takes an opaque `Store.t`;
clients see `Result<Update, Error>`'s normal public
schema; projection structs and borrowed storage do not become client types.

`Encoded::new` finishes encoding before it returns. Its output owns bytes and any
transferred owning handles, with no borrowed references retained. The generated
export can therefore finish its call-scoped store borrow before lowering the
result. The dedicated return lowering moves the populated encoder buffer into
the output arena; it does not serialize into a second vector or copy that buffer.
The buffered output owns its body and UTF-8 pool as separate segments.
Regenerate Rust and glue together when changing the private ABI.

Encoder byte, item and depth limits still apply. Encoding failures retain the
ordinary boundary-error path. Dropping a failed or unused encoded value releases
any owning handles already transferred into its encoder; output-arena cleanup
handles resources after successful publication.

## Supported boundaries

- Generated exports accept `Encoded<Result<Value, Error>>` only as the complete
  return type of a synchronous function. This keeps its ABI consistent with the
  buffered result schema.
- Nested `Encoded` values fail encoding. Async exports reject this return type;
  their ordinary owning result path remains available.
- `Encoded` is thread-affine because transferred opaque handles belong to their
  originating thread's arena.
- `EncodeProjection` derives projections for concrete records and enums. Generic
  owned declarations are rejected. The generated projection itself is generic
  over its field representations.
- `EncodeAs<T>` is the extension point for custom projections. Implementations
  must preserve `T`'s codec contract; prefer derived projections and standard
  sequence projections to handwritten encoders.
